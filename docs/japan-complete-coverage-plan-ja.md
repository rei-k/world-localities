# 日本の行政区・道路・番地を完全網羅する実行計画

作成日：2026-10-22。状態：計画策定済み、追加取得・全国網羅の検証は未実施。

全国の公式台帳を土台に、自治体別の不足を閉じていく。先に行政区・町字の基準を固め、住居表示と地番を別系統で取得し、道路形状と通り名を照合する。公開資料だけで確認できない範囲も全国の対象一覧に残す。配達可能性は対象外。

## 1. 今あるデータを出発点にする

以下は既存リリースの収録実績であり、現時点の日本の公式総数・一意住所数・網羅率ではない。

| 既存資料 | 収録実績 | 再利用と不足 |
|---|---:|---|
| [日本公式台帳](../official-registry/JP/README.md) | 47都道府県、1,912市区町村・区 | 指定都市の親20件を含む。元資料1,918市区町村行のうち6行は未解決。最新の公式名簿との差分と、この6行の扱いを最初に確認 |
| 同台帳の日本郵便資料 | 124,526郵便行 | 郵便上の住所表記の補助。町字・番地の全件名簿にはしない |
| [東アジア取込](../releases/hierarchy/east-asia/README.md)：ABR由来OpenAddresses | 21,984,066住居資料行 | 位置情報と結合できた部分集合。座標なしの住居番号・地番の不足を別に取得 |
| 同：Geolonia町丁目位置参照 | 277,658行 | 名称・位置の照合補助。公式町字IDへ無条件に置換しない |
| 同：日本OSM抽出 | active道路way 10,661,600件、番地タグ260,624観測 | 一意道路数・住所数ではない。選択PBFだけでは全参照節点が揃わず、道路形状は未組立 |

既存の公式台帳は2026-09-25取得のABRを再利用したもの。2026-10-01と東アジア取得時の公式CDN取得失敗は、保存済み台帳の不存在を意味しない。取得日・原典の基準日・法的な施行日を区別して残す。

## 2. 「完全」の対象を固定する

世界管理表の4分野を維持し、日本向けに下位区分を持たせる。

| 分野 | 対象 | 完了に必要な確認 |
|---|---|---|
| 行政区・住所階層 | 都道府県、市区町村、特別区、指定都市とその区、町・大字・丁目・小字等の公的住所単位 | 基準日時点の公式対象名簿、コード、親子関係、改廃履歴に欠落・未解決がない |
| 住所用の通り | 道路方式で使う道路名、京都の通り名等の住所表現、住所検索に使われる通称 | 制度上の住所要素と案内上の通称を区別し、適用地域・原典・表記を照合する。通りを用いない区域は根拠付きで非該当とする |
| 物理道路 | 国道・都道府県道・市町村道に加え、農道・林道・里道・私道等、現存する道路・通路の対象分類 | 道路管理台帳と地図資料に照らし、名称の有無を問わず形状・区間・状態を確認。車道、歩道、歩行者道等の分類と重複を定義する |
| 割当済みの番号 | 住居表示の街区符号・住居番号・枝番号、地番の本番・支番、公式に確認できる特殊表記 | 実在する番号の全件一覧に照合する。住居表示と地番を別の名前空間に置き、廃止番号と現行番号を分ける |

行政の郡・支庁／振興局等、統計上の地域、自治会等は種類を分ける。住所階層に機械的に挿入しない。町字名簿にない小字等は自治体資料から追加調査し、未確認のまま全国完了にしない。

建物・部屋の名称や室番号の全件収録は今回の完了条件に加えない。ただし、公式住居番号の一部をなす枝番号等は保持する。地番は土地の識別情報として全件取得を目指すが、すべての筆に住所・建物があるとは扱わない。

地理的範囲は原典の管轄・収録範囲を記録して定める。離島、住所のない区域、境界未定・所属未定の原典記載も対象管理から落とさない。原典の主張、実際の管理、取得可否を別に記録し、帰属を推定して6件等の未解決行を強制統合しない。

## 3. 取得する原典と使い分け

2026-10-22に下記の一次資料を確認した。掲載ページの確認と、データ本体の取得・全件検証は別の作業である。

| 優先 | 原典 | 使う情報・確認した制約 |
|---|---|---|
| 1 | [S1 デジタル庁ABR方針](https://www.digital.go.jp/policies/base_registry_address)、[S2 データカタログ](https://dataset.address-br.digital.go.jp/) | 公式の都道府県・市区町村・町字マスター。町字の文字情報は正式版、地番・住居表示等は試験公開の位置付け。町字ID修正一覧も取得対象 |
| 1 | [S3 総務省の全国地方公共団体コード](https://www.soumu.go.jp/denshijiti/code.html)、[S4 J-LISコード一覧](https://www.j-lis.go.jp/spd/code-address/jititai-code.html)、[S5 e-Stat市区町村検索](https://www.e-stat.go.jp/municipalities/cities/areacode) | 自治体・指定都市の区の対象と改廃を照合。総務省ページは今回の閲覧で取得できず、再確認が必要。J-LISの一括提供は利用者向けであり、無条件のオープン配布とは扱わない |
| 2 | ABRの住居表示-街区・住居マスターと位置参照拡張、自治体の住居表示台帳・実施区域・新旧対照表・告示 | 文字の全件表を先に取り込み、座標を後から付与する。試験公開ABRだけで全国全件を保証しない |
| 2 | [S6 法務省地図データ公開案内](https://www.moj.go.jp/MINJI/minji05_00494.html)、[S7 G空間の公式配布案内](https://front.geospatial.jp/moj-chizu-xml-readme/)、[S8 デジタル庁のXML変換説明](https://www.digital.go.jp/news/4b7250a3-3fcf-4b83-8d52-4bb131e1ba9d) | 地図XMLの筆・町字・地番。公共座標と任意座標を区別する。S6/S7の本文取得は今回403であり、配布資源の一覧・版・規約は実行時に取得して確認する |
| 3 | [S9 国土数値情報・道路N13](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N13-2024.html) | 2026年4月公開の2024年度版、基準は2024年9月。CC BY 4.0の道路中心線。メッシュ単位で全配布資源を列挙する。ノード・リンク構造はなく、道路名・全私道の全件台帳としては使わない |
| 3 | [S10 国土地理院・基盤地図情報](https://www.gsi.go.jp/kiban/)、各道路管理者・自治体の公開道路台帳 | 道路縁、行政界、管理区間等の照合候補。基盤地図の道路縁と道路中心線を同じ地物として数えない。収録仕様・再配布条件・利用手続を資源ごとに確認する |
| 補助 | 既存OSM、Geolonia、OpenAddresses、日本郵便 | 未一致候補・表記・位置の照合。複数ソースの単純合計を全国総数にしない |
| 注意 | [S11 国土地理院「住居表示住所」](https://www.gsi.go.jp/kihonjohochousa/jukyo_jusho.html) | 基礎番号の位置資料で、個別建築物や割当済み住居番号の全件表ではない。実在住所の自動生成には使わない |

ABRの将来の整備については、[S12 住所・所在地情報管理システムの共通化](https://www.digital.go.jp/policies/base_registry_address/standardization)も確認する。将来の整備計画を、現在取得できる全国全件データと混同しない。

## 4. 実行する順序と完了条件

| 段階 | 実行内容 | 段階を終える条件・成果物 |
|---|---|---|
| P0 対象と取得経路 | 既存公式台帳・東アジア資料を棚卸しし、最新の自治体対象名簿を固定。ABRの現行カタログから配布URL・分割単位を解決。4分野の自治体別管理表を作成 | 全対象に管理行があり、旧版・未取得・非該当・不明を区別できる。既存6未解決行に調査票を用意 |
| P1 行政区・町字 | ABRの文字マスターを全分割取得し、総務省等のコード・自治体告示と照合。町字ID修正一覧、旧新ID、改称・廃止・親子関係を処理 | 公式対象全件が一意に追跡でき、欠落・重複・孤立参照・未解決をゼロにする。取得不能の対象が残れば全国完了にしない |
| P2 住居表示 | 住居表示実施区域を確定し、街区・住居の文字マスターを全件取得。自治体台帳で未収録と更新差分を補う | 実施区域内の割当済み番号を台帳と照合。座標なしを含め全件保持し、非実施区域の地番調査へ接続 |
| P3 地番 | ABR地番と法務省地図XMLを原典単位で取得。図面・筆ID・本番・支番・町字・座標系を保持し、自治体の地番現況資料等と照合 | 文字上の地番収録と地図上の位置付けを別に検証。地図XMLにない筆・未登記等の番号不明範囲があれば、対象・不足を残す |
| P4 道路・通り名 | N13全公開メッシュ、道路管理台帳、利用可能な地理院資料を照合。OSMは元データから依存節点を取得して形状を組立。住所用の通り名は別台帳で管理 | 未収録の管理区間・通り名を解決し、農林道・里道・私道・歩行通路の調査対象にも状態を付ける。全国の道路全体の分母が確認できなければ、N13取込完了と全国完了を分ける |
| P5 自治体別の不足解消 | 公開CSV/GIS→公開PDF・図面→告示等の順に不足を調査。自治体内の町字・区域まで掘り下げて照合する | 4分野の未取得・未照合・矛盾・分母不明がすべて解消。原典全件再読込、差分照合、検索検証、復元検証を通す |
| P6 公開と更新 | 原典の版を固定したリリース、出典、件数、欠落、対応コミットを管理表へ記録。以後、原典変更に追随できる差分取得・改廃処理を実装 | 再取得・再変換・復元が可能で、同じ基準時点に対する検証結果を再現できる。更新遅延も公表 |

依存関係は P0→P1→P2/P3/P4→P5→P6。P1で対象IDを確定後、住居表示・地番・道路の取得は独立した処理として進められる。未公開資料の調査は待ち行列に残し、他地域の作業を進める。実行時の担当数や並行実行は別途決める。

最初の検証は8〜12自治体を目安に、東京の特別区、指定都市、札幌型の条丁目、京都型の通り名、地番中心、小字・甲乙等、農山村、離島を含める。候補の採否はP0で公開原典を確認して決める。これで番号の分解・型・座標・地図XML処理を確認してから47都道府県へ広げる。都市部だけで全国完了を判断しない。

## 5. データを欠落・誤統合させない規則

- 文字の主表に位置表を左結合する。緯度経度の欠損で住所行を落とさず、文字収録率と座標付与率を別に示す。
- LGコード・町字ID・街区ID・住居ID・筆ID等は原典の文字列を保持する。公式IDがない場合は原典と版に限定した内部IDを使い、公式IDだと表示しない。既存の `locality:jp:lg:` IDとの対応を明示する。
- 番号は整数化しない。枝番、先頭ゼロ、甲乙丙丁、ノ・の・之、番外・無番地等は原典表記を保持する。「1〜100」から100件の実在番号を生成しない。
- 正規化表記・読み・別名・旧名を原文と分ける。ABR町字IDの修正は公表された対応を使い、同名町字・通り名・異体字を名前だけで統合しない。京都関係の修正一覧も対象にする。
- 住居番号・筆・建物・道路は別の実体にする。地番と住居表示の対応は多対多を許容し、近接座標だけで同一と断定しない。対応が不明でも原典行は保持する。
- 任意座標の地番は文字索引へ収録し、緯度経度として扱わない。JGD2011/JGD2024等の測地系名、EPSG、元座標、版・時点を保持し、名称変更だけを根拠に座標値を変換しない。
- OSMのway数、道路台帳の路線数、幾何形状の分割区間数を区別する。立体交差を同一平面の接続とみなさない。道路の無名確認と名称未取得も区別する。
- 不一致は候補表へ残す。原典ごとの値を保持し、公式資料同士の矛盾を黙って上書きしない。

## 6. 自治体別管理表と達成率

全国の基準名簿に載せた全対象を、都道府県→市区町村／区→町字／実施区域へ掘り下げて管理する。指定都市の親と区は二重計上せず、同じ公表単位へ集約するための対応表を持つ。

管理行に最低限必要な項目：

| 項目 | 内容 |
|---|---|
| 対象 | LGコード、町字ID等、親、区域・管理者、分野・下位分類 |
| 原典 | URL、提供者、資料名、資源ID、取得日、データ基準日、施行日、版、利用条件、SHA-256 |
| 状態 | 未調査／取得可能／取得済み／照合済み／全件確認済み／取得不能・未公開／根拠付き非該当 |
| 分母と照合 | 全件性の根拠、対象総数、同時点の照合先、取得件数、一意件数、照合済み件数、欠落・重複・矛盾・座標欠損 |
| 証跡 | 照合方法、確認者または検証処理の版、未解決理由、次の作業、リリースとGitコミット |

率は次を分けて公表する。

1. **原典の取込率**：原典に含まれる対象行のうち、欠落なく保存・変換できた割合。同じファイルの全件再読込で検証する。
2. **自治体の確認完了率**：全国対象名簿のうち、その分野で全件確認を終えた対象の割合。原典未公開・分母不明の対象を分母から落とさない。非該当数も別に示す。
3. **項目別の収録率**：公式に対象全体を列挙した同時点の名簿に対し、公式キー等で一致を確認した件数÷対象総数。分母の全件性や対象範囲を確定できなければ `null` とし、観測行数から推定しない。
4. **位置・形状の収録率**：文字上の存在確認とは別の指標。道路は基準形状に対する区間・延長等を対象範囲付きで示す。測量精度・分割方法・基準時点が違う道路延長統計を、そのまま正確な網羅率の分母にはしない。

原典の全件取込100%は、その原典が全国の現存実体を全件列挙する証明にはならない。全件性を説明する原典の対象仕様と、可能な独立照合先を確保する。独立照合ができない場合は、その検証の限界を残す。

全国の完全網羅の判定は、全対象・4分野で分母と時点が確定し、欠落・未解決がゼロになった場合に限る。補助率の平均で全国の「100%」を作らない。座標未確認が残る場合も、文字全件確認と位置全件確認を分けて表示する。

## 7. 調達上の難所と解決順

| 難所 | 次の対応 | 未解決時の扱い |
|---|---|---|
| ABRのCDNで403 | 現行カタログ・仕様から正規の配布経路と分割単位を確認し、取得ログを残す。原典由来が確認できる保存版・再配布物は版を明示して利用 | 古い資料で代替した対象は旧版と表示し、最新取得済みにしない |
| 自治体がCSVを公開していない | 再利用条件を確認した公開GIS・PDF・台帳図を調査。OCRは候補抽出とし、原図との全件照合を行う | 原典が非公開・閲覧限定なら不足として残す。外部への提供依頼が必要な対象を一覧化する |
| 全国の私道・通路や割当番号の分母が公開されていない | 分野・区域・管理者ごとに公式資料の対象を分解し、既知の穴と分母不明を識別する | 公開データだけで全国全件を証明できるとは約束しない。取得可能範囲の完了を示し、全国判定は未達を維持する |
| 版が異なる・更新後の番号が未反映 | 取得時点と基準時点を分離し、新設・廃止・改称・分合筆等を履歴化する | 同時点へ合わせられない対象は照合未完了とする |

取得規模や必要な自治体資料が未確定のため、現段階では全国完了日を設定しない。P0と先行自治体の検証後、残る対象数と取得難度から見積もる。

## 8. 最初の実装・公開単位

既存のCLIと公式台帳を再利用し、以下の順で小さく更新する。ファイル名は今後の実装案であり、この計画で作成済みとするものではない。

| 更新単位 | 主な成果物案 | 公開条件 |
|---|---|---|
| J1 全国対象・原典索引 | `jp-targets`、`jp-source-catalog`、自治体別の不足表、6未解決行の調査票 | コード・分野・原典・版・未取得理由を確認 |
| J2 公式行政区・町字 | ABRの原典、町字索引、公式ID対応・修正履歴、全件照合結果 | J1の分母に対する不足・親子参照を検証 |
| J3 住居表示 | 座標なしを含む住居主表、位置表、実施区域、自治体別照合 | 原典再読込と文字／位置の別集計を検証 |
| J4 地番 | 図面・筆・地番索引、公共／任意座標の区別、未対応表 | 原典XMLとの照合、重複図面・筆の扱いを検証 |
| J5 道路・通り名 | 全資源マニフェスト、形状、管理路線対応、住所用通り名 | メッシュ欠落・参照節点・形状・対象分類を検証 |
| J6 不足解消・全国判定 | 自治体別達成率、全国判定、差分更新・復元手順 | 全件性の根拠、未解決ゼロ、同一版の再現性を確認 |

コード・原典索引・検証結果・対応コミットをGitHubへ更新し、大容量原典は通常Gitと分離して復元索引を付ける。既存リリースの証跡は書き換えず、新しい版で進捗を記録する。この計画の追加だけで、東アジアの `national_completeness_verified` や既存の網羅率を引き上げない。
